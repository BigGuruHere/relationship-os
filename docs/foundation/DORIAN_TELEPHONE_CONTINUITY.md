# Dorian telephone continuity

The existing inbound Dorian agent can serve active Foundation accounts with a verified Australian mobile. For this pilot, the incoming number provisionally identifies the account for the call. That gives Dorian access to the account's eligible call context and lets a completed consented call update its Living Understanding. It grants no account login or channel verification. Unmatched numbers continue through the provisional telephone flow.

App and telephone use the same Foundation initiation module. A feature can supply a purpose with its own objective, conversation context and opening question. Both channels use the same private self subject, transcript queue, full LU assessment and operator review. The operator queue shows App or Telephone and the source records the capture channel alongside the existing provider and turn provenance. A queued call in the current vault and enrollment blocks another launch with a short processing message. An analysis in operator review lets the participant call again using the latest approved understanding.

The app uses its checkbox and sends `terms_agreed: true` after recording or recognising the current agreement. The telephone sends `terms_agreed: false` when agreement is required, and Relish queues the existing policy SMS with the current legal page. When `relish_terms_status` is `REQUIRED`, ElevenLabs owns the opening and consent wording. Relish leaves the first message to the agent and supplies an empty `call_instruction` through the webhook contract. The agent asks for explicit agreement and calls the existing voice tool. Use `relish_terms_sms_status` to describe whether a notice was queued or sent. After an accepted tool result it uses the returned `startup_context`. Consent is scoped to the policy version and its two document URLs. There is no SMS identity challenge.

## Hosted DEV setup

Apply `20261124010000_dorian_foundation_telephone` before enabling telephone continuity. For a local development database use `npx prisma migrate dev`.

- Keep the existing Foundation browser configuration and set `RELISH_FOUNDATION_DORIAN_PHONE_AGENT_ID` to the shared inbound DEV Dorian agent ID. This is a separate agent ID from the browser agent. Use the existing shared binding, authenticated initiation webhook and signed post-call transcription webhook.
- Set `RELISH_PILOT_CONVERSATIONAL_TERMS=YES` with published Relish documents, the HTTPS DEV app origin and the existing Telnyx SMS settings. Foundation terms notices in DEV only queue for numbers in `RELISH_EXCHANGE_TEST_PHONES`. Use the environment's existing exchange realm and encryption configuration.
- After verifying [Dorian's legal overview](https://doriankreed.com/legal/) and both full policies on the public domain, set `DORIAN_PHONE_POLICY_VERSION=dorian-kreed-2026-11-25-v1`. This enables the Dorian-branded link and records voice acceptance against the Dorian documents. The app still checks its Relish policy separately. A participant who changes channels may need to agree to the other policy once. Leave this variable unset to keep the existing shared-policy behaviour. The pilot still uses the same private account and LU across channels.
- Enable First message overrides and the built-in `end_call` tool. The telephone prompt should follow agent-owned consent instructions when `{{relish_terms_status}}` is `REQUIRED`, and use any nonempty `{{call_instruction}}` supplied for other call states. Use the existing legacy dynamic-variable defaults for standalone agent tests. On a processing-only or unavailable response, have Dorian speak the first message and invoke `end_call`.
- The existing `record_relish_policy_acceptance` tool posts to `/api/webhooks/elevenlabs/tools/record-policy-acceptance` using `ELEVENLABS_TOOL_SECRET`. Bind `conversation_id` and `relish_network_session` to provider runtime values and collect `agreement=true` only after explicit agreement. When the tool returns `ACCEPTED` with `startup_context`, use that context for the rest of the call. Use the returned processing message followed by `end_call` if a concurrent call returns `PROCESSING`. An error or refusal ends the call.
- Confirm both provider agents' completed transcripts are readable with the existing ElevenLabs API key. Turning off `RELISH_FOUNDATION_DORIAN_PHONE_AGENT_ID` returns new calls to the original routing. Keep the additive migration and existing evidence.

## Hosted acceptance

1. Start in the app and accept by checkbox. Confirm the launch sends `terms_agreed: true` and the operator can review the call. Call from the verified mobile after approving a topic. With the Dorian policy configured, check the Dorian link and agree by voice before verifying recall. A subsequent telephone call should skip the consent prompt and SMS.
2. Introduce a new substantive detail by telephone. Check that the call appears once under Operator tools and that its evidence points to the telephone source. Approve it and verify continuity on an app call.
3. Use a second account with a verified mobile and no current agreement. Confirm that the phone receives the policy SMS, initial context contains no private memory, and the agent records explicit agreement through the tool. With the Dorian policy configured, confirm the app separately requests Relish terms. Repeat with refusal or hang-up and verify that nothing enters the LU queue.
4. Call back on both channels while analysis is queued, then again while the result is waiting for operator review. Check the processing message, the release for subsequent calls, and isolation between the two accounts. Also verify legacy routing for an unmatched number and that a revoked mobile cannot enter the Foundation path.

## Phone-first accounts

When `RELISH_DORIAN_PHONE_FIRST=YES`, a direct call from an Australian mobile can provision a private Foundation account, self subject and unpublished profile. A current verified account takes precedence. Otherwise the incoming number provisionally routes calls to the same phone-first account. The pending phone carries no login, verified-channel or contact-claim authority. Voice terms and the usual processing, review and recall rules apply from the first call.

On the signup page, callers choose **Activate app access**, enter their mobile and request the existing SMS verification code. The code is bound to the requesting browser. Successful proof and email/password activation commit together on the existing account. Calls, terms, LU and evidence keep their original owner and source identifiers. The verified channel is available to the existing contact-claim flow. Phone-first activation uses email and password. People who already created a separate app account require an explicit ownership resolution before their histories can be combined.

Apply `20261124020000_dorian_phone_first` after the telephone continuity migration. The phone-first flag defaults off. DEV activation uses the existing exchange database binding and test-mobile allowlist. Production activation of app access uses the existing production exchange target and SMS settings. To roll back intake, turn off `RELISH_DORIAN_PHONE_FIRST` and retain the migration and stored records. Existing SMS invitations and callbacks still use their current workflow.

For hosted verification, call from a new DEV-approved mobile, decline terms once and then accept on a fresh call. Complete a call, approve an LU topic and call again. Confirm recall, then activate app access from signup using the SMS code. Verify the signed-in account has the same terms and recall, and that wrong codes and codes submitted in another browser are denied. Repeat with a verified existing account and a withheld number.
