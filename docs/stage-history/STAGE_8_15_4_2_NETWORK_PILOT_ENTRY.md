# Stage 8.15.4.2 - Network Pilot Entry and Personal QR Sharing

## Objective

Deliver the first small Network pilot surface on the Stage 8.15.3.5 baseline. Network is a user-facing experience backed by the **existing General ContextSpace**, not a new database domain. Reuse the existing Profile, public `/u/[slug]` and QR sharing implementation. Do not launch additional account-claim or conversation workflows in this stage.

## Source changes

- `/network`: authenticated Network entry page with a simple My Profile panel.
- `/network/share`: selects a profile belonging to the signed-in user with `kind: personal` and redirects to `/share?profile=<slug>`. It never silently chooses a Business or Dating profile.
- `src/lib/server/core/contextDomain.ts`: Network URLs resolve to the existing General domain so future operations can use the same governed boundary.
- `settings/profile`: supports selecting a personal profile when opened with `?kind=personal`, or an exact profile with `?profile=<slug>`. Creation of a personal profile does not overwrite the default Business profile.
- Shared General sidebar: Network is available as an ordinary member entry; existing operator routes remain capability-controlled.
- `check:stage8.15.4.2` source-contract tests.

## Important boundaries

- This is **not** the complete invitation flow. The existing public profile connection action remains as previously implemented. It has **not** yet been verified to create a connection in the inviter's General/Network ContextSpace.
- No provisional identity creation, account claim, Dorian session handoff, or post-call LU proposal is added.
- No new Prisma migration and no historical migration modifications.
- The General ContextSpace must still be configured for future Network conversation processing. Network is a user-facing label, not a new `domainKey`.
- The QR SVG is generated by the existing `/share` endpoint, which remains owner-scoped.
- Existing public profile endpoints and legacy share URLs retain their prior behaviour and require end-to-end security review before untrusted pilot use.

## Manual UI acceptance

### Test 1 - Network entry
- [ ] Sign in and open `/network`.
- [ ] Confirm the Network title and simple profile panel appear.
- [ ] Confirm an ordinary member is not exposed to the General operator inbox on this screen.

### Test 2 - Personal profile creation
- [ ] If you only have a Business profile, select **Create my profile**.
- [ ] Confirm the editor defaults to **Personal**.
- [ ] Save a new personal profile.
- [ ] Return to `/network` and confirm the new personal profile appears.
- [ ] Verify your existing Business profile has not changed.

### Test 3 - Network QR sharing
- [ ] Click **Share my QR** on `/network`.
- [ ] Confirm the QR share view corresponds to the personal profile, not Business.
- [ ] Copy its public URL, open in a private browser, and check only intentionally public profile information is visible.
- [ ] Confirm QR encodes the same personal profile URL.

### Test 4 - No personal profile fallback
- [ ] With a development user who has only a Business profile, open `/network/share` directly.
- [ ] Confirm redirection to personal-profile creation, not the Business QR.

### Test 5 - Regression
- [ ] Existing Business contact-note workflows still open and save.
- [ ] General operator Review Inbox is still restricted to operator capability.
- [ ] Existing Dorian ingestion and authoritative LU review still operate as before.
